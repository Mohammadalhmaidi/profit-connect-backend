# نظام المصادقة (Auth) — توكن الوصول + ريفرش توكن

نظام جلسات مزدوج: **توكن وصول قصير** للطلبات + **ريفرش توكن طويل** للتجديد التلقائي.

## المسارات

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/auth/signup` | إنشاء حساب + إرجاع `token` و`refreshToken` |
| POST | `/api/auth/login` | تسجيل الدخول + إرجاع `token` و`refreshToken` |
| GET | `/api/auth/me` | المستخدم الحالي (محمي بـ `protect`) |
| POST | `/api/auth/refresh` | تجديد الجلسة (تناوب: يُبطل القديم ويُصدر جديداً) |
| POST | `/api/auth/logout` | إبطال الريفرش توكن من الخادم |

## الاستجابة عند الدخول/التسجيل
```json
{
  "success": true,
  "token": "eyJ...",          // توكن وصول (JWT_EXPIRE)
  "refreshToken": "eyJ...",   // ريفرش (JWT_REFRESH_EXPIRE_DAYS يوم — افتراضياً 30)
  "user": { }
}
```

## تجديد الجلسة
```
POST /api/auth/refresh
```
```json
{ "refreshToken": "eyJ..." }
```
- يتحقق: التوكن غير مُلغى (`revokedAt`) ولم تنتهِ صلاحيته.
- **تناوب (Rotation):** يُصدر `token` + `refreshToken` جديدين، ويُبطِل القديم (يُسجَّل `replacedBy`).
- ريفرش مسروق/مُعاد استخدامه → 401.

## تسجيل الخروج
```
POST /api/auth/logout
```
```json
{ "refreshToken": "eyJ..." }
```
يُبطَل الريفرش من قاعدة البيانات → الجلسة تنتهي فعلياً من الخادم.

## الأمان
- الريفرش **لا يُخزَّن خاماً** أبداً — يُخزَّن SHA-256 Hash في `RefreshToken` مع `expiresAt` و`revokedAt` و`replacedBy`.
- الريفرش توكن **لا يصلح** كتوكن وصول — `protect` يرفض أي توكن `type: refresh` برسالة إرشادية.
- `RefreshToken` ينتهي تلقائياً (TTL index على `expiresAt`).

## متغيرات البيئة
| المتغير | الافتراضي | المعنى |
|---|---|---|
| `JWT_EXPIRE` | — | صلاحية توكن الوصول |
| `JWT_REFRESH_EXPIRE_DAYS` | `30` | صلاحية الريفرش توكن بالأيام |

## نصيحة للفرونت
- التخزين المقترح: توكن الوصول في الذاكرة، والريفرش في **كوكي HttpOnly**.
- على استجابة 401 من `protect`: استدعِ `/refresh` تلقائياً ثم أعد الطلب مرة واحدة.
