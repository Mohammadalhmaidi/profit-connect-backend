# النظام المالي في منصة Profit Connect — دليل كامل

نظام مالي مبني على **الحساب الضامن (Escrow)**: العميل يدفع للمنصة، والمبلغ محجوز، ولا يُحرَّر إلا عند اكتمال المشروع — ثم يمكن للمستلم سحب رصيده.

> ملاحظة: النظام الحالي **تجريبي** — الأرقام افتراضية داخل قاعدة البيانات، لا توجد بوابات دفع حقيقية ولا تحويلات فعلية.

---

## 1) المفاهيم الأساسية

| المصطلح | المعنى |
|---|---|
| **الحساب الضامن (Escrow)** | مبلغ دفعه العميل ومحجوز لدى المنصة، لا يملكه أحد بعد |
| **محفظة المستخدم** | حساب داخلي لكل مستخدم يضم أربعة أرصدة |
| **الدفعة المحجوزة (Held)** | مبلغ وصل للمنصة بانتظار التحرير |
| **التحرير (Release)** | نقل صافي المبلغ من الحساب الضامن إلى محفظة المستلم (بعد خصم العمولة) |
| **الاسترجاع (Refund)** | إعادة المبلغ المحجوز إلى محفظة العميل (نزاع/إلغاء) |
| **طلب السحب (Withdrawal)** | طلب يُرسله المستخدم لسحب رصيده، يقرّه فريق الدعم |

### محفظة المستخدم (حقول `wallet` في حساب المستخدم)
| الحقل | المعنى |
|---|---|
| `balance` | **الرصيد المتاح للسحب** (القابل للسحب فعلياً) |
| `holding` | مبلغ محجوز لطلب سحب قيد المراجعة (غير قابل للسحب) |
| `totalEarned` | إجمالي ما كسبه المستخدم منذ البداية |
| `totalWithdrawn` | إجمالي ما سحبه فعلياً |

---

## 2) دورة المال خطوة بخطوة

```
① العميل يدفع (فيزا/مدى/...)  ──►  الدفعة تصبح Held لدى المنصة (الحساب الضامن)
② [لا أحد يستطيع سحب هذا المبلغ إطلاقاً]
③ اكتمال المشروع + اعتماد  ──►  التحرير: يخصم عمولة المنصة، والصافي يصل لمحفظة المستلم
④ المستلم يرى الرصيد في balance  ──►  يطلب السحب (ينتقل لـ holding)
⑤ موافقة الدعم  ──►  المبلغ يخرج نهائياً (ترتفع totalWithdrawn) — يُحول له خارجياً
⑥ رفض الدعم  ──►  يعود المبلغ تلقائياً إلى balance
```

### حالات الدفعة (`PlatformPayment.status`)
- `held` → `released` (محررة للمستلم) · `refunded` (مسترجعة للعميل) · `cancelled`

### حالات طلب السحب (`Withdrawal.status`)
- `pending` → `processed` · `rejected` · `cancelled`

## 3) كل المسارات المالية

### أ) مسارات المستخدم — `/api/wallet` (يتطلب تسجيل دخول)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/wallet` | **عرض محفظتي**: الرصيد القابل للسحب + المحجوز + السجل |
| POST | `/api/wallet/withdraw` | طلب سحب رصيد |
| GET | `/api/wallet/withdrawals` | طلبات السحب الخاصة بي |
| POST | `/api/wallet/withdrawals/:id/cancel` | إلغاء طلب سحب معلّق (يعيد المبلغ) |

### ب) مسارات الدفعات — `/api/payments` (يتطلب تسجيل دخول)

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/payments` | إيداع دفعة في الحساب الضامن (صاحب المشروع فقط) |
| GET | `/api/payments` | كل الدفعات المتعلقة بي (مدفوعة أو مستلمة) |
| GET | `/api/payments?direction=received&status=held` | فلترة: `direction=received` دفعات وصلت لي / `direction=sent` دفعات أرسلتها، و`status=held/released/refunded` |
| PUT | `/api/payments/:id/release` | تحرير الدفعة لمحفظة المستلم (العميل أو الأدمن) |

### ج) مسارات إدارة المنصة — `/api/admin/finance/*` (أدمن فقط)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/admin/finance/overview` | نظرة مالية شاملة (محجوز، عمولات، سحوبات معلقة...) |
| GET | `/api/admin/finance/withdrawals?status=` | كل طلبات السحب مع فلترة |
| PUT | `/api/admin/finance/withdrawals/:id` | موافقة/رفض طلب سحب |
| GET | `/api/admin/finance/payments?status=` | كل الدفعات مع فلترة |
| POST | `/api/admin/finance/payments/:id/release` | تحرير يدوي |
| POST | `/api/admin/finance/payments/:id/refund` | استرجاع (إلغاء/نزاع) |
| PUT | `/api/admin/finance/settings` | ضبط نسبة عمولة المنصة |

## 4) سؤال: ما الـ API الذي يرى فيه المستخدم رصيده القابل للسحب؟

> **`GET /api/wallet`**

الاستجابة:
```json
{
  "success": true,
  "data": {
    "wallet": {
      "balance": 4500,        // ← الرصيد القابل للسحب الآن
      "holding": 500,         // ← محجوز لطلب سحب قيد المراجعة
      "totalEarned": 9000,
      "totalWithdrawn": 4000
    },
    "transactions": [
      { "type": "release", "amount": 4500, "description": "تحرير دفعة من الحساب الضامن إلى محفظتك", "createdAt": "..." }
    ]
  }
}
```

**قاعدة ذهبية:** المبلغ القابل للسحب = `data.wallet.balance` فقط. أمّا `holding` فمبلغ غير قابل للسحب حالياً (سحب قيد المراجعة)، و`balance` + `holding` = إجمالي ما يملكه المستخدم في محفظته.

## 5) أمثلة عملية على الطلبات

### طرق الدفع المدعومة (حقل `method`)
| الطريقة | القيمة في النظام | حصة سوق المدفوعات | ملاحظات |
|---|---|---|---|
| PayPal | `PayPal` | 26.24% | الأكثر شيوعاً في 107 دولة |
| Visa | `Visa` | 13.60% | خيار أساسي لأي متجر إلكتروني |
| Mastercard | `Mastercard` | 8.33% | تغطية عالمية مشابهة لـ Visa |
| American Express | `American Express` | 6.85% | شائعة في أمريكا الشمالية ورسومها أعلى |
| Apple Pay | `Apple Pay` | 5.25% | دفع سريع بالبصمة/الوجه لمستخدمي Apple |

### طلب سحب رصيد
```
POST /api/wallet/withdraw
```
```json
{
  "amount": 500,
  "method": "bank_transfer",
  "accountDetails": {
    "bankName": "مصرف الراجحي",
    "iban": "SA0000000000000000000000",
    "holderName": "محمد أحمد"
  }
}
```
النتيجة: ينقص `balance` بـ500 ويرتفع `holding` بـ500، ويظهر الطلب بحالة `pending`.

### موافقة الأدمن على السحب
```
PUT /api/admin/finance/withdrawals/6790a...abc
```
```json
{ "action": "approve", "note": "تم التحويل" }
```
النتيجة: `holding` ينقص بـ500، و`totalWithdrawn` ترتفع بـ500. الطلب يصبح `processed`.

### رفض الأدمن للسحب
```json
{ "action": "reject", "note": "رقم الآيبان غير صحيح" }
```
النتيجة: `holding` ينقص و`balance` يعود كما كان، والطلب يصبح `rejected`.

### إيداع دفعة في الحساب الضامن
```
POST /api/payments
```
```json
{
  "projectId": "6790a...123",
  "proposalId": "6790a...abc",
  "amount": 5000,
  "method": "Visa",
  "note": "الدفعة الأولى"
}
```
- **`method` مطلوب** — يحدد المستخدم طريقة الدفع، والخيارات: `PayPal` · `Visa` · `Mastercard` · `American Express` · `Apple Pay`.
- **الدفعة تُربط بعرض (Proposal):** عند تمرير `proposalId` يُرسل المبلغ تلقائياً لصاحب **العرض المقبول** (`status: Accepted`) لذلك المشروع، ويُحفظ في حقل `proposal`.
- بديل: يمكن تمرير `payeeId` صريح بدلاً من `proposalId` (بشرط أن يكون عضواً في فريق المشروع).
- يتأكد النظام أن الدافع هو صاحب المشروع وأن المستلم عضو في الفريق.
- الدفعة تُنشأ بحالة `held` — لا يمكن لأحد سحبها، ولا يزيد رصيد المستلم إلا عند التحرير (`release`).

### تحرير الدفعة (الاعتماد)
```
PUT /api/payments/6790a...789/release
```
- يتأكد النظام أن المحرِّر هو العميل (الدافع) أو الأدمن.
- تُخصم عمولة المنصة (افتراضياً 10%) ويصل صافي المبلغ لمحفظة المستلم.
- مثال: دفعة 5000 → عمولة 500 → الصافي 4500 يصل لـ `balance` للمستلم.

## 6) سجل الحركات (`MoneyTransaction`) — متابعة كل شيء

كل عملية مالية تُسجَّل ويمكن للمستخدم رؤيتها في `GET /api/wallet` ضمن `transactions`:

| النوع | المعنى | أثر على balance |
|---|---|---|
| `release` | تحرير دفعة من الحساب الضامن | + |
| `fee` | عمولة المنصة | − |
| `refund` | استرجاع دفعة | + |
| `withdraw` | طلب سحب (عند الإنشاء) | − |
| `withdraw_refund` | إلغاء/رفض سحب وإعادة المبلغ | + |
| `withdraw_processed` | تنفيذ السحب (خروج نهائي) | 0 (يخصم من holding) |
| `manual` | حركة يدوية (للأدمن مستقبلاً) | حسب الحالة |

## 7) الإشعارات المرتبطة بالمال

تُعرض عبر `GET /api/projects/notifications`، وتحمل كل إشعارات المال بيانات مساعدة: `paymentId` (للدخول لصفحة الدفعة) + `withdrawalId` + `amount` + `method`.

| النوع | متى يصل | يُرسل لـ |
|---|---|---|
| `payment_deposited` | عند إيداع دفعة | المستلم |
| `payment_released` | عند التحرير | الطرفين |
| `payment_refunded` | عند الاسترجاع | الطرفين |
| `withdrawal_approved` | عند موافقة الدعم على السحب | طالب السحب |
| `withdrawal_rejected` | عند رفض السحب | طالب السحب |

**مثال إشعار دفعة:**
```json
{
  "type": "payment_deposited",
  "message": "تم إيداع دفعة لك في الحساب الضامن لمشروع «تطبيق توصيل»",
  "paymentId": "6790a...789",
  "projectId": "6790a...123",
  "amount": 5000,
  "method": "Visa",
  "read": false
}
```

### كيف يرى المستخدم أن هناك دفعة له؟
1. **الدفعة نفسها:** `GET /api/payments?direction=received` → كل الدفعات التي أنت مستلمها (بما فيها المحجوزة `held`).
2. **رصيده الفعلي:** `GET /api/wallet` → `data.wallet.balance` (لا يُضاف الرصيد إلا بعد التحرير).
3. **الإشعار:** `GET /api/projects/notifications` → إشعار `payment_deposited` يصل فور الإيداع.

## 8) ملاحظات أمان وتجريبية
- كل تحويل مالي محمي بـ **حارس حالة** (`findOneAndUpdate` بشرط الحالة) يمنع التحرير/الخصم المزدوج.
- سحب أكثر من `balance` مرفوض تلقائياً (شرط ذري).
- للنسخة الحقيقية: يُربط النظام ببوابة دفع (Moyasar/Tap/PayTabs) لإنشاء الفواتير واستقبال الأموال، وتُترقى حركات الأموال إلى `mongoose.transaction` لضمان الذرية الكاملة.
- قانونياً: تقديم مدفوعات للغير قد يتطلب ترخيصاً — استشر مختصاً.
